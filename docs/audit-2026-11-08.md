# Code audit, 8 November 2026

Hiren asked for an adversarial audit of code quality before the next round of features: design patterns, clean code, extensibility, SOLID, Laravel practice. Four independent reviewers read the whole codebase, each told to prove the code wrong from one angle (architecture and SOLID; Laravel practice and security; correctness under failure; dead code and readiness for the next features). Their findings were merged here, duplicates folded together, and the important ones re-checked by hand. "Verified" means reproduced with a scratch test or a command on this laptop or the server; the rest were traced through the code by at least one reviewer. Nothing was changed while auditing.

## Verdict

Not ready for testers yet, and close. The architecture is sound and most of it follows its own rules: ports with fakes, write actions with one transaction and an event after commit, the answer chain, commands from config, the model chain, the citation check on the profile. What is wrong is concentrated in three places: the answer handlers grab messages that are not theirs, the kept-message retry is not safe to repeat, and old code from before the current design is still wired in. Tier 1 below is about two focused days; tier 2 is the clean-up that makes the next features cheap.

## Tier 2: fix before the next features

These do not lose data today, but each next feature (injury-aware plans, body map, knowledge notes, shadow classifier, WhatsApp, the app writing) would be built on top of them.

1. **Two doors that disagree.** `POST /api/log` handles only plain logs: a limitation returns 422 with an empty message, a coach question gets "Asking the coaches over chat is coming soon". `Interpretation` is a bag of nullable fields read in a different order by each door. Fix: one outcome type (record, record limitation, ask coach, reply) used by both doors through `RespondToText`. (`SmartLogController.php:57-61`, `Interpretation.php`, `Interpreter.php:40`)
2. **Delete what the design left behind.** Nutrition still runs inside every log call (prompt, schema, `RecordSmartLog`, `RevertSmartLog`, meal types defined three times); the old trainer and plan stack (`TrainerAgent`, `PlanAgent`, `SdkTrainerChat`, `SdkPlanGenerator`, `/trainer`, `/plans`, `ProfileIntake`) contradicts the current coach rules ("never diagnose... see a professional", "Latika, a holistic nutritionist") and skips the model chain; the RPG stat sheet is served but never written; the Intent lab duplicates the classifier lab; `WorkoutSessionController` is a second write path with no activity log, no sets, no event; `diary_entries` is a hand-synced copy of `activity_logs.summary` nobody reads. The Nuxt app calls five routes; about fifteen others have no client. One cleanup round (M3 plus these) removes roughly 2,000 lines.
3. **One exercise vocabulary.** Names live in three unrelated lists with two normalisations (`ExerciseAliases`, `ExerciseLoads`, `PersonalRecordService` keywords). `ExerciseLoads` matches substrings: crunch loads the knee and ankle (it contains "run"), leg curl loads the elbow, push-up loads nothing (verified). "Bench Press Barbell" is a separate lift from "Bench Press". Fix: an exercise catalogue keyed by the canonical name with muscle group, joints loaded and kind, and one strength calculator (best set, estimated one-rep max) that records, starting loads and the body map all read. The body map needs this; `BodyArea` lists joints, not muscle groups.
4. **Loads computed in PHP, not in the prompt.** The coach prompt says "never calculate your own" and then "about two thirds of that lift's top set". Compute suggested loads from the strength calculator and put them in the context.
5. **The classifier seam.** Plain rules run inside each AI adapter and the fake (copied three times); the interpreter branches on the string `'rules'`; the two System One adapters disagree on `Command`; nothing stores classifications, so a shadow run has nowhere to write; `laravel/ai`'s own `Classification` is unused while `SystemOneClient` duplicates it unmetered. Fix: rules in the interpreter, `decidedBy` as an enum, a shadow decorator with a table.
6. **Open questions as a typed thing.** Every handler re-derives "is this mine" from `questions[0]['field']` strings. An `OpenQuestion` with a kind enum, and `openFor` finding the newest log that has an open question (today a newer log orphans an older question).
7. **Dependencies that point the wrong way.** Domain code tags AI calls with adapter class names (`ClassifierAgent::class` in the interpreter, coach and profile), so swapping a provider still names SDK agents; `TrainerChat` (a port) imports from `App\Ai`; `App\Channels` and `App\Conversation` use each other; `KeepMessage` (an action) takes the transport's `InboundMessage`. Fix: an `AiJob` enum for tagging, a `ChatChannels` registry by provider, receipt wording in `Conversation`.
8. **Adapters with hidden state.** `modelName()` on the coach and profile ports only means something after a call; return the model with the answer instead.
9. **`AnswerCoachQuestion` does five jobs** (daily cap, monthly budget, context, AI call, storing the turn) and `CoachContext::for` is a static that resolves its own collaborators. Split out the allowance; make the context builder injectable. Likewise `RecordSmartLog` switches on `LogType` and so do three other classes: one recorder per type.
10. **Indexes and queries.** Postgres does not index foreign keys: `workout_sessions(user_id, logged_at)`, `exercise_entries(workout_session_id)` and `(activity_log_id)`, `body_weight_logs(user_id, logged_at)`, `diary_entries`, `limitations` and `limitation_updates` on `activity_log_id` have none. `ExerciseLine` re-queries sets even when loaded; `PersonalRecordService` loads every session ever, several times per request. Add the indexes, eager-load, and turn on `preventLazyLoading` outside production.
11. **Tests that could call Gemini.** `SmartLogParser` has no default fake in `TestCase`, nothing blocks stray HTTP, the AI keys are not blanked in `phpunit.xml`; `FakeSmartLogParser` returns a shape the real adapter never returns (no `set_list`, still meal fields). Bind every AI fake, add `Http::preventStrayRequests()`, blank the keys.

## Tier 3: smaller, schedule when convenient

- Dates and daily caps are UTC: a log at 00:30 Amsterdam lands on the previous day. Per-user timezone (default Europe/Amsterdam).
- `/better knee` heals the newest injury, not the knee; commands drop their arguments.
- Undoing a limitation update leaves its new end date.
- Natural answers to "3 sets of 5 or 5 sets of 3?" ("3x5", "3 sets of 5") are not taken.
- Kept messages are handled after newer ones: `/undo` can remove the wrong log.
- The scheduler loop (`sleep 60`) drifts and can skip the weekly profile rebuild; use `schedule:work`.
- A missing `APP_KEY` in production is silently replaced by a random one; fail instead.
- The sign-in token is in the URL query (`?token=`); a fragment keeps it out of server logs.
- Query exceptions and the poller's reply excerpts can put message text (injuries) in logs.
- The poller handles one message at a time and agents have the library's 60 s timeout: one hung model blocks everyone. Short timeouts on classify and parse.
- Duplications: number formatting four times, `skip` four times, the limitation shape twice, exercise-entry JSON two shapes, sanity limits three times with different values.
- Stale docblocks: `User::waitingMessages` ("newest first", wrong return type), `RecordSmartLog` ("Telegram in M5"), `UpdateUserStats` ("Redis queue"), `Interpretation` (two stacked docblocks), "front desk" used nowhere else.
- `AiCall` logs `config('ai.default')` (openai) as the provider.
- Email case: login and profile update do not lowercase; Postgres `unique` is case-sensitive.
- Unpinned build inputs (`install-php-extensions` latest, `composer:2`); `expose_php` on.
- `TrainingDaysPerWeek` dispatches a stats job from inside a profile question; `ProfileCheckIn::next()` writes while sounding like a query.

## What is good and should stay

- Every live AI call goes through a port with a fake; the suite runs with zero model calls (once tier 2 item 11 closes the gap).
- Write actions (`RecordSmartLog`, `RecordLimitation`, `RecordLimitationUpdate`, `RevertSmartLog`): one transaction, `setRelation` instead of re-querying, the event after commit.
- Commands and answer handlers from config: one class and one line; the Telegram menu comes from the same list.
- Named interpretation rules: small, ordered, testable.
- `UpdateProfile`'s citation check keeps model output from becoming fact.
- `ModelChain` keeps failover in one place; `ExerciseLine` words an exercise once for every reader.
- Security basics: php-fpm on loopback with a build check, one exposed port, hashed single-use invite and login codes with locks and expiry, owner-scoped queries (no cross-user access to logs or limitations), trusted proxies limited, `env()` only in config, registration closed in production.

## The tests

A fifth reviewer audited the suite (310 tests, 8.5 s SQLite, 13 s Postgres). The readable version, with the code findings, is `docs/technical/audit.html`.

- Purpose: about 215 tests guard product behaviour and read as a spec; about 34 guard legacy code scheduled for deletion; about 17 pin framework wiring or prompt text; the coach, limitation and profile adapters have no contract test.
- Strength: `AiUsageTest:65-72` asserts the "every error is an outage" bug, and `InterpreterTest:39-49` pins "coaches coming soon" for the app door. Every fake's `failing()` throws `RuntimeException`, so the outage tests depend on that bug. `FakeSmartLogParser` does not return the real adapter's shape (no `set_list`). Several assertions pass when the behaviour breaks (the adherence cap, the retry delay, "12 kg is not reps").
- Why the tier 1 bugs passed: every chat test sends only the input the handler expects; none sends the message a greedy handler would steal.
- Speed: four failed-login tests take 3.3 s (39%) because Laravel pads each failed login to 200 ms (`auth.timebox_duration`); set it to 0 in tests for a ~5 s run.
- Isolation: a full run made zero AI requests (measured with a spy server), but only by care: real keys reach the test process, the log parser has no default fake, nothing blocks stray HTTP.
- Missing: the ten tests listed in the HTML report, starting with the reproductions of tier 1.
